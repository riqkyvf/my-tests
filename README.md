# PomidorQA — автотесты на Python

[![CI](https://github.com/riqkyvf/my-tests/actions/workflows/tests.yml/badge.svg)](https://github.com/riqkyvf/my-tests/actions/workflows/tests.yml)

Проект функциональных автотестов для [PomidorQA](https://aiqa.su/pomidorqa) —
сервиса поиска собеседников по навыкам и бронирования коротких встреч для QA/IT-специалистов.

**Стек:** Python 3.14 · pytest · синхронный Playwright · Allure · Ruff.

Тесты выполняются на стенде `https://aiqa.su`.

## Быстрый запуск

**Окружение:** Python 3.14, Windows, PowerShell.
Команды выполняются из корня проекта.

```powershell
py -3.14 -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
.\.venv\Scripts\python.exe -m playwright install chromium
.\.venv\Scripts\python.exe -m pytest -m smoke
```

Smoke-набор включает три сценария: UI-регистрацию, вход и бронирование с проверкой
встречи у обеих сторон. По умолчанию используется Chromium без видимого окна.
Аккаунты создаются для каждого теста и удаляются фикстурами после его завершения,
в том числе при падении проверок.

## Покрытие

В наборе **78 случаев с учётом параметризации** для Chromium: 77 UI и одна
техническая API-проверка сессионной cookie.

| Область | Основные проверки |
| --- | --- |
| Регистрация и авторизация | Регистрация, валидация форм, вход, выход и доступ к защищённым страницам |
| Профиль и навыки | Сохранение данных, добавление и удаление навыков, отображение изменений другому участнику |
| Слоты и часовые пояса | Создание и удаление слотов, запрет прошлого времени, время и дата в поясе владельца |
| Каталог и публичный профиль | Доступность участников, поиск по навыку «могу помочь», отображение свободных слотов |
| Бронирование и встречи | Встреча у обеих сторон, роли ведущего и гостя, конкуренция двух гостей за слот |
| Отмена | Двухчасовое ограничение, отмена каждой стороной, освобождение и повторная бронь слота |

Основной E2E-сценарий: аккаунты через API → навык и слот через UI → профиль
ведущего из каталога гостя → бронь → проверка встречи у обеих сторон и статуса слота.
UI-регистрация и ввод поискового запроса проверяются отдельными сценариями.
Полный перечень проверок и их границы — в [матрице покрытия](coverage_matrix.md).

## Устройство проекта

```text
tests/              Сценарии, проверки и шаги Allure
pages/              Локаторы страниц и действия пользователя (Page Objects)
components/         Общие компоненты интерфейса
api/                Создание и удаление аккаунтов через Playwright APIRequestContext
helpers/            Генерация пользователей и работа с датами
conftest.py         Фикстуры, фабрики данных и очистка
config.py           Адреса, таймауты и часовой пояс по умолчанию
pytest.ini          Настройки pytest и маркер smoke
pyproject.toml      Настройки Ruff
docs/               Архитектура, CI и диагностика
```

Данные каждого теста независимы; участники работают в отдельных браузерных
контекстах. Аккаунты для подготовки создаются через API, остальные данные —
через UI. Устройство фикстур и авторизации описано в [docs/architecture.md](docs/architecture.md).

## Запуск тестов

Полный набор:

```powershell
.\.venv\Scripts\python.exe -m pytest
```

## Allure-отчёт

Для генерации отчёта используется Node.js 24 с npm/npx.

```powershell
.\.venv\Scripts\python.exe -m pytest --alluredir=allure-results --clean-alluredir
npx.cmd --yes allure@3.21.0 awesome allure-results --single-file --output allure-report --group-by feature --report-language ru
Start-Process .\allure-report\index.html
```

Отчёт содержит результаты тестов и шаги сценариев, подготовки и очистки данных.
Флаг `--clean-alluredir` очищает результаты предыдущего запуска.

## Качество кода и CI

```powershell
.\.venv\Scripts\python.exe -m ruff check .
.\.venv\Scripts\python.exe -m ruff format --check .
```

[GitHub Actions](https://github.com/riqkyvf/my-tests/actions/workflows/tests.yml)
проверяет Ruff и запускает smoke-набор при push и pull request в `main`.
При ручном запуске **Run workflow** доступны `smoke` — три основных сценария
(регистрация, вход и бронирование) и `full` — полный набор из 78 случаев.
Окружение CI: Ubuntu 24.04, Python 3.14 и Chromium.

После первого падения CI запускает тест повторно. При успешной второй попытке
тест считается пройденным; повторное падение завершает шаг тестов с ошибкой.
Результаты и HTML Allure сохраняются в **Artifacts** на семь дней;
при неуспешных попытках добавляются trace и скриншоты.
Режимы запуска и артефакты описаны в [docs/ci.md](docs/ci.md).

## Ограничения

- Стенд внешний: его доступность и время ответа могут влиять на результат.
- Проверки прошедших слотов, начавшихся встреч и точной границы отмены требуют
  подготовки данных или управления временем сервера.
- HTML-валидация и отсутствие кнопки в UI не доказывают серверный запрет
  при прямом HTTP-обходе.
- Фактическая длительность слота недоступна для проверки: интерфейс не выдаёт
  `end_time`, а подпись «25 минут» не подтверждает серверную длительность.

Подробные ограничения указаны у соответствующих требований в матрице покрытия.
